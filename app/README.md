# مرصد الشكاوى الرقمية

تطبيق ويب محلي لتحليل الشكاوى العربية واستعراضها ومراجعتها. الواجهة React وTypeScript وVite وTailwind، والخادم FastAPI وPydantic وSQLAlchemy، وقاعدة البيانات SQLite. لا يستخدم Streamlit.

## التشغيل السريع

الأوامر التالية من **جذر المشروع** الذي يحتوي المجلدين `app/` و`ml/`:

```bash
python3 -m venv app/backend/.venv
app/backend/.venv/bin/python -m pip install -r app/backend/requirements.lock
npm --prefix app/frontend ci
npm --prefix app run start
```

إذا كانت الاعتماديات مثبتة بالفعل يكفي الأمر الأخير. تم التحقق باستخدام Python 3.12.7 وNode 22.20.0 وnpm 10.9.3. استخدم Node 22.20 أو إصدار LTS أحدث متوافق مع Vite.

- الموقع: <http://127.0.0.1:5173>
- Backend: <http://127.0.0.1:8000>
- عقد REST وواجهة تجربة الطلبات: <http://127.0.0.1:8000/docs>
- OpenAPI: <http://127.0.0.1:8000/openapi.json>

التشغيل يربط الخادمين بواجهة loopback فقط. `Ctrl+C` يوقفهما. لا توجد حسابات أو خدمات مدفوعة أو اتصالات ML سحابية. الخط العربي مستضاف ضمن ملفات التطبيق.

لتشغيل كل جزء منفصلًا من جذر المشروع، في نافذتين:

```bash
app/backend/.venv/bin/python -m uvicorn app.backend.main:app --host 127.0.0.1 --port 8000
npm --prefix app/frontend run dev -- --host 127.0.0.1
```

## ما تم تنفيذه في P0

1. لوحة المؤشرات: الرسائل والشكاوى ونسبتها والمراجعات وتوزيع الفئات والأنظمة والاتجاهات.
2. تحليل شكوى: نص وبيانات مصدر اختيارية، واستيراد CSV مع تقرير الصفوف.
3. مستكشف الشكاوى: بحث وفلاتر وترقيم صفحات وتفاصيل.
4. تحليلات الأنظمة: حصة كل نظام وتوزيع المشكلات فيه.
5. طابور المراجعة: تصحيح حالة الشكوى والفئة واسم النظام، مع سجل تعديل.
6. معلومات الموديل: وضع التشغيل والنسخ المرصودة وحدود النتائج وتقارير التقييم عند توافرها.

الواجهة عربية RTL ومتجاوبة. يظهر الوضع التجريبي بوضوح في جميع الصفحات. الأعراض الواردة في الرسائل لا تثبت عطلًا أو سببًا هندسيًا.

## تجربة Mock

الوضع الافتراضي `mock` ولا يستورد حزمة `ml` إطلاقًا. النتائج ثابتة لأغراض اختبار دورة التطبيق، وليست نموذجًا مدربًا:

| النص المطابق | النتيجة |
|---|---|
| رمز التحقق لا يصل عند تسجيل الدخول | AUTH |
| التطبيق لا يفتح ويغلق فجأة | AVAIL |
| التطبيق بطيء | PERF |
| خصم المبلغ ولم يكتمل الطلب | TRANS |
| زر التأكيد لا يظهر | UX |
| الخدمة فيها مشكلة | OTHER |
| شكرا التطبيق ممتاز | غير شكوى |
| أي نص آخر | OTHER ويحتاج مراجعة |

جميع درجات Mock هي `null` وجميع سجلاته `is_demo=true` حتى لو أرسل العميل خلاف ذلك. لا توجد أرقام F1 أو Accuracy مصطنعة.

من صفحة التحليل نزّل عينة DEMO ثم ارفعها؛ الملف نفسه في `frontend/public/demo.csv`. العينة تحتوي 8 رسائل اصطناعية بلا تواريخ نشر. إعادة استيرادها لا تضاعف العدد. لا يتم تحميل fixtures تلقائيًا أو حذف البيانات تلقائيًا.

## CSV والمدخلات

```csv
text,source_id,source_app,original_event_time
رمز التحقق لا يصل عند تسجيل الدخول,review-001,تطبيق المصدر,2026-10-29T12:30:00+03:00
التطبيق بطيء,review-002,,
```

- `text` مطلوب، نص غير فارغ حتى 20,000 حرف.
- `source_id` و`source_app` و`original_event_time` اختيارية. معرف المصدر واسم التطبيق حتى 200 حرف.
- CSV بترميز UTF-8 مع قبول BOM، حتى 10MB و5,000 صف. الأعمدة غير المعروفة تُتجاهل، ولا يتم تنفيذ الخانات أو جلب روابطها.
- الصف الفاسد يسجل رقمه وسبب الفشل، دون إلغاء الصفوف السليمة. CSV غير المقروء أو فاقد `text` يُرفض.
- إذا توقف النموذج الحقيقي أثناء استيراد، تبقى الصفوف السابقة المحفوظة ويعرض التقرير نقطة التوقف والسبب، ولا يدعي استكمال الملف.
- المصدر `source_app` يحدد النظام في P0؛ لا يتم تخمين أسماء الأنظمة من النص.
- التاريخ الأصلي المفقود يبقى `null`. التواريخ بلا منطقة زمنية تُفسر بتوقيت الرياض، والتخزين UTC والعرض بتوقيت الرياض. التجميع الأسبوعي يبدأ الاثنين.
- منع التكرار بمعرف المصدر ضمن المصدر والتطبيق ونطاق Demo/Real؛ بدونه نستخدم بصمة النص المنقح والسياق والتاريخ الأصلي. لا نمنع رسائل مستقلة بمعرفات مختلفة لمجرد تشابه النص.
- إدخالات الاختبار في وضع Real يمكن وسمها صراحة `is_demo=true` من الواجهة أو API. البادئة المحجوزة `DEMO-` في معرف المصدر تفرض Demo لحماية ملف العينة عند استخدام النموذج الحقيقي.

## معنى الإحصاءات والتصحيحات

إجمالي الرسائل هو عدد السجلات بعد إزالة إعادة الاستيراد. الشكاوى عدد الرسائل ذات الحالة الحالية `is_complaint=true`. التوزيع حسب الفئة يستخدم الشكاوى فقط، وتعرض الشكاوى غير المصنفة منفصلة.

حصة النظام هي عدد الشكاوى المرتبطة به ÷ جميع الشكاوى في النطاق المختار، بما فيها غير محدد النظام. كل رسالة لها نظام وفئة رئيسية واحدة في P0.

`data_scope=real` افتراضي في API؛ واجهة Mock تختار `demo` صراحة. لا يوجد جمع تلقائي بين النطاقين. تصحيح سجل Demo لا يحوله إلى بيانات حقيقية.

رسوم النشر تستبعد السجلات بلا تاريخ أصلي وتعرض عدد الشكاوى غير المؤرخة ضمن نطاق المصدر/النظام، قبل فلتر الفترة التي لا يمكن إسنادها إليها. اختيار «وقت الاستيراد» يعرض نشاط إدخال البيانات، وليس تاريخ حدوث المشكلة. النقاط الزمنية المعروضة هي الفترات التي تحتوي شكاوى؛ لا تُختلق تواريخ أو أعداد لفترات غير مرصودة.

التصحيحات تحفظ داخل معاملة واحدة وتؤثر على القيم الحالية والمؤشرات. التوقع الأصلي ونسخته ودرجاته تبقى محفوظة في `original_prediction`، واسم النظام الأصلي محفوظ. درجات النتيجة الأصلية لا تصف بالضرورة الفئة التي صححها الإنسان. لا يوجد تدريب تلقائي أو تعديل لأوزان ML.

## قاعدة البيانات والخصوصية

قاعدة SQLite المحلية: `app/backend/storage/complaints.sqlite3`، مستبعدة من Git. إنشاء الجداول غير هدام. الاختبارات تستخدم قواعد منفصلة مؤقتة.

التنقيح يحجب أنماط البريد الإلكتروني وأرقام الجوال السعودية والهوية ذات الشكل المعروف قبل التصنيف والتخزين، ويطبّق على اسم النظام أيضًا. هذه قواعد محدودة؛ لا تضمن إزالة جميع الأسماء أو المعلومات الشخصية. لا يُحفظ الملف المرفوع أو النص الخام. راجع البيانات قبل مشاركة القاعدة.

`DATABASE_URL` يسمح باختيار قاعدة أخرى. النماذج واستعلامات التجميع قابلة للنقل، لكن **لم يُنفذ أو يُختبر ترحيل PostgreSQL**. نقل البيانات وتثبيت driver وخطة migration لاحقة؛ `create_all` ينشئ الجداول الناقصة ولا يحدّث بنية جدول موجود تلقائيًا. انسخ قاعدة البيانات احتياطيًا قبل أي تغيير مستقبلي للبنية.

## دمج نموذج Claude

```bash
APP_ML_MODE=real npm --prefix app run start
```

يجب أولًا تثبيت اعتماديات `ml/` المتوافقة في بيئة Backend نفسها بواسطة صاحب النموذج، والتأكد من وجود artifacts. التطبيق يستدعي فقط:

```python
from ml.infer import predict_text
result = predict_text("التطبيق بطيء")
```

تبقى المفاتيح الستة المتفق عليها كما هي. اختيار Real لا يتطلب تغيير صفحات React. النموذج الغائب أو النتيجة المخالفة للعقد ينتجان خطأ HTTP 503 صريحًا؛ لا fallback إلى Mock ولا إعادة تحليل تلقائي للسجلات السابقة.

صفحة المعلومات تعرض «لم يُختبر بعد» حتى ينجح استدلال حقيقي. ملفات تقييم Claude لا تملك عقد JSON مشتركًا، لذلك لا نحللها لاختراع Metrics. يمكن إتاحة تقرير نصي محلي للقراءة فقط:

```bash
APP_ML_MODE=real \
APP_EVALUATION_REPORT="/absolute/path/to/ml/reports/evaluation.md" \
APP_EVALUATION_MODEL_VERSION="exact-model-version" \
npm --prefix app run start
```

يظهر التقرير فقط إذا تطابقت نسخته المحددة مع نسخة آخر استدلال Real ناجح. يعرض كنص المصدر لا HTML. مسؤولية صحة التقرير ونسبته للنموذج لصاحب تقرير ML. التطبيق لا يحسب أو يولد تقييمًا علميًا.

## الاختبارات والبناء

من جذر المشروع:

```bash
app/backend/.venv/bin/python -m pytest app/backend/tests -q
npm --prefix app/frontend test
npm --prefix app/frontend run build
```

التحقق يشمل اختبارات Pytest وVitest ودورة متصفح فعلية. راجع `PROGRESS.md` لنتائج الأوامر المنفذة و`INTEGRATION_NOTES.md` لحدود قبول النموذج الحقيقي.

## متابعة التنفيذ والاستعادة

- `IMPLEMENTATION_PLAN.md`: المهام والمراحل وحالاتها ومعايير قبولها.
- `PROGRESS.md`: سجل متزايد للنتائج المتحققة، بما فيه الإخفاقات التي صُححت.
- `SESSION_HANDOFF.md`: حالة الاستئناف والأوامر والخطوة التالية.

عند الاستئناف اقرأ المتطلبات والوثائق الثلاث، ثم افحص المصدر وGit ونتائج الاختبارات؛ لا تعتمد على الوثائق وحدها. كل العمل في مستودع `app/` المستقل، ولا يعدل `ml/` أو يندمج أو يدفع تلقائيًا.

## الواجهة ثنائية اللغة والتحليلات المطورة

زر **عربي / EN** أعلى الموقع يبدل لغة التنقل والعناوين والأزرار والنماذج، ويغيّر الاتجاه إلى RTL أو LTR. يُحفظ الاختيار محليًا في المتصفح تحت المفتاح `marsad.language`، والعربية هي الافتراضية. محتوى الشكاوى وأسماء الأنظمة وفئات النموذج والنتائج البحثية لا تُترجم ولا تُرسل لخدمة ترجمة، وتبقى الأرقام التحليلية بصيغتها العربية.

الداش بورد المطورة تضيف:

- رسمًا دائريًا لتوزيع الفئات وروابط تنقل إلى الرسائل التابعة لكل فئة.
- ترتيب الأنظمة مع روابط إلى رسائل النظام، ومصفوفة «نظام × فئة» في تحليلات الأنظمة مع البحث والفرز وعرض البطاقات.
- مؤشرات اكتمال بيانات أسماء الأنظمة وتواريخ النشر، ونسبة الرسائل التي لا تتطلب مراجعة إضافية **حسب حالتها الحالية**. هذه ليست دقة للنموذج ولا دليلًا على مراجعة بشرية فعلية لكل رسالة.
- مزيج المصادر: عدد الرسائل وعدد الشكاوى لكل من الإدخال النصي وCSV.
- مقارنة عدد الشكاوى بالفترة السابقة المساوية في عدد الأيام عند اختيار **بداية ونهاية** للفترة. تحافظ المقارنة على المصدر والنظام ونطاق Demo/Real وأساس التاريخ. نسبة التغير غير متاحة إذا كان عدد الفترة السابقة صفرًا.
- اختصارات آخر 7/30 يومًا حسب توقيت الرياض، وإمكانية عرض نشاط الاستيراد الفعلي عند غياب تواريخ نشر.

مؤشرات الاكتمال تخص السجلات ضمن الفلاتر الحالية؛ نسب الأنظمة والتواريخ تُحسب من الشكاوى، ومؤشر عدم الحاجة للمراجعة من جميع الرسائل. محتوى النموذج والتقارير وأسباب أخطاء المصدر تظل كما وردت دون إعادة صياغة آلية.
