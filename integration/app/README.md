# مرصد الشكاوى الرقمية

تطبيق ويب محلي لتحليل الشكاوى العربية واستعراضها ومراجعتها. الواجهة React وTypeScript وVite وTailwind، والخادم FastAPI وPydantic وSQLAlchemy، وقاعدة البيانات SQLite. لا يستخدم Streamlit.

## P1: النصوص ولقطات الشاشة

فرع التنفيذ الحالي `integration/p1` يضيف OCR المحلي ثم مراجعة النص وتصحيحه قبل MARBERT، مع أدلة الأنظمة المذكورة وحفظ أصل التحليل والتصحيحات. لا بريد إلكتروني أو EML أو تدريب جديد. تعليمات التثبيت والعقود والرجوع في [P1_SETUP.md](P1_SETUP.md)، ونتائج الفحص والقيود في [P1_INTEGRATION_VERIFICATION.md](P1_INTEGRATION_VERIFICATION.md).

**قبول التشغيل بالمتصفح ما زال معلّقًا:** البيئة الحالية تمنع فتح منافذ localhost (`EPERM`) وتمنع تشغيل المتصفح، وVision يعيد engine_error داخل sandbox. المسار الحقيقي عبر FastAPI وEasyOCR وMARBERT وSQLite اختُبر داخل العملية؛ هذا لا يُعد تحققًا ناجحًا بالمتصفح. لا تُغيّر اختبارات ML لتجاوز هذا القيد.

## التشغيل السريع

نسخة الدمج المعتمدة موجودة داخل `Project/integration/` على الفرع `integration/p1` (مع حفظ فرعي دمج A4 وV1 السابقين). المجلدان الأصليان `Project/app/` و`Project/ml/` محفوظان كما كانا. **نفّذ جميع الأوامر التالية من داخل `integration/`** الذي يحتوي نسختي `app/` و`ml/`:

```bash
# في النسخة المحلية الجاهزة يكفي:
npm --prefix app run start

# إعداد بيئة P1 مستقلة في checkout جديد عند الحاجة:
unset PYTHONPATH PYTHONHOME
python3.12 -m venv app/backend/.venv-p1
app/backend/.venv-p1/bin/python -I -m pip install --require-hashes --only-binary=:all: -r app/backend/requirements-p1-macos-arm64-py312.lock
npm --prefix app/frontend ci
cp -n app/.env.example app/.env
npm --prefix app run start
```

بيئة P1 المستقلة `backend/.venv-p1` تثبّت 66 حزمة للإعداد الأساسي مع Vision، أو77 حزمة عند تثبيت fallback EasyOCR. بيئة A4 المستقرة `backend/.venv-a4-standalone` محفوظة دون تغيير. لا PYTHONPATH أو حزم خارجية. ملفات lock خاصة بـPython3.12 وmacOS ARM64؛ يحتاج Vision نظامًا يدعم ar-SA. الإعدادات المحلية تختار EasyOCR صراحةً بسبب قيد sandbox، بعد التحقق من أوزانه المحلية. راجع [P1_SETUP.md](P1_SETUP.md) للتثبيت والعمل دون إنترنت، و[ENVIRONMENT_SETUP.md](ENVIRONMENT_SETUP.md) لنسخة A4 المستقرة.

في checkout جديد انسخ ملفي V1 الأصليين إلى `ml/artifacts/`، وملف A4 `model/model.safetensors` إلى التصدير المتتبّع `ml/artifacts/a4/export/a4-marbert-v1/`. الأوزان الكبيرة مستبعدة من Git. البصمات في `MODEL_ASSETS.json` و`A4_MODEL_ASSETS.json`، والتحقق من A4 بواسطة `shasum -a 256 -c SHA256SUMS` داخل مجلد التصدير. **لا تعِد تدريب النموذج أو تقييم holdout لتشغيل التطبيق.** تم التحقق باستخدام Python 3.12.7 وNode 22.20.0 وnpm 10.9.3. استخدم Node 22.20 أو إصدار LTS أحدث متوافق مع Vite.

- الموقع الحالي لـA4: <http://127.0.0.1:15174>
- Backend الحالي: <http://127.0.0.1:18174/docs>
- القيم الافتراضية عند غياب إعدادات المنفذ: الموقع `5173` وBackend `8000`. تم ضبط `APP_WEB_PORT=15174` و`APP_API_PORT=18174` محليًا لأن خدمات أخرى كانت تستخدم المنافذ المعتادة؛ لم تُوقف تلك الخدمات.
- OpenAPI على `/openapi.json` في منفذ Backend المختار.

التشغيل يربط الخادمين بواجهة loopback فقط. `Ctrl+C` يوقفهما. لا توجد حسابات أو خدمات مدفوعة أو اتصالات ML سحابية. الخط العربي مستضاف ضمن ملفات التطبيق.

لتشغيل جزء منفصلًا من `integration/`، حمّل الإعدادات في نافذته أولًا (npm launcher يفعل ذلك تلقائيًا):

```bash
set -a
source app/.env
set +a
app/backend/.venv-p1/bin/python -m uvicorn app.backend.main:app --host 127.0.0.1 --port "${APP_API_PORT:-8000}"
# في نافذة أخرى بعد تحميل الإعدادات نفسها:
npm --prefix app/frontend run dev -- --host 127.0.0.1
```

## ما تم تنفيذه في P0

1. لوحة المؤشرات: الرسائل والشكاوى ونسبتها والمراجعات وتوزيع الفئات والأنظمة والاتجاهات.
2. تحليل شكوى: نص وبيانات مصدر اختيارية، واستيراد CSV مع تقرير الصفوف.
3. مستكشف الشكاوى: بحث وفلاتر وترقيم صفحات وتفاصيل.
4. تحليلات الأنظمة: حصة كل نظام وتوزيع المشكلات فيه.
5. طابور المراجعة: تصحيح حالة الشكوى والفئة واسم النظام، مع سجل تعديل.
6. معلومات الموديل: وضع التشغيل والنسخ المرصودة وحدود النتائج وتقارير التقييم عند توافرها.

الواجهة عربية RTL ومتجاوبة. يظهر الوضع التجريبي بوضوح في جميع الصفحات. الأعراض الواردة في الرسائل لا تثبت عطلًا أو سببًا هندسيًا.

## تجربة Mock

الوضع الافتراضي للمحرك `real`. عند تحديد `ML_ARTIFACT_DIR` كما في `.env` المحلية و`.env.example` يُحمّل A4؛ عند غياب هذا الإعداد يُحمّل `tfidf-baseline-v1` كما كان. يتم التحميل محليًا عند بدء FastAPI. لتجربة Mock المستقل شغّل `APP_ML_MODE=mock npm --prefix app run start`؛ هذا الوضع لا يستورد حزمة `ml` إطلاقًا. النتائج ثابتة لأغراض اختبار دورة التطبيق، وليست نموذجًا مدربًا:

| النص المطابق | النتيجة |
|---|---|
| رمز التحقق لا يصل عند تسجيل الدخول | AUTH |
| التطبيق لا يفتح ويغلق فجأة | AVAIL |
| التطبيق بطيء | PERF |
| خصم المبلغ ولم يكتمل الطلب | TRANS |
| زر التأكيد لا يظهر | UX |
| الخدمة فيها مشكلة | OTHER |
| شكرا التطبيق ممتاز | غير شكوى |
| أي نص آخر | OTHER ويحتاج مراجعة |

جميع درجات Mock هي `null` وجميع سجلاته `is_demo=true` حتى لو أرسل العميل خلاف ذلك. لا توجد أرقام F1 أو Accuracy مصطنعة.

من صفحة التحليل نزّل عينة DEMO ثم ارفعها؛ الملف نفسه في `frontend/public/demo.csv`. العينة تحتوي 8 رسائل اصطناعية بلا تواريخ نشر. إعادة استيرادها لا تضاعف العدد. لا يتم تحميل fixtures تلقائيًا أو حذف البيانات تلقائيًا.

## CSV والمدخلات

```csv
text,source_id,source_app,original_event_time
رمز التحقق لا يصل عند تسجيل الدخول,review-001,تطبيق المصدر,2026-10-29T12:30:00+03:00
التطبيق بطيء,review-002,,
```

- `text` مطلوب، نص غير فارغ حتى 20,000 حرف.
- `source_id` و`source_app` و`original_event_time` اختيارية. معرف المصدر واسم التطبيق حتى 200 حرف.
- CSV بترميز UTF-8 مع قبول BOM، حتى 10MB و5,000 صف. الأعمدة غير المعروفة تُتجاهل، ولا يتم تنفيذ الخانات أو جلب روابطها.
- الصف الفاسد يسجل رقمه وسبب الفشل، دون إلغاء الصفوف السليمة. CSV غير المقروء أو فاقد `text` يُرفض.
- إذا توقف النموذج الحقيقي أثناء استيراد، تبقى الصفوف السابقة المحفوظة ويعرض التقرير نقطة التوقف والسبب، ولا يدعي استكمال الملف.
- المصدر `source_app` يحدد النظام في P0؛ لا يتم تخمين أسماء الأنظمة من النص.
- التاريخ الأصلي المفقود يبقى `null`. التواريخ بلا منطقة زمنية تُفسر بتوقيت الرياض، والتخزين UTC والعرض بتوقيت الرياض. التجميع الأسبوعي يبدأ الاثنين.
- منع التكرار بمعرف المصدر ضمن المصدر والتطبيق ونطاق Demo/Real؛ بدونه نستخدم بصمة النص المنقح والسياق والتاريخ الأصلي. لا نمنع رسائل مستقلة بمعرفات مختلفة لمجرد تشابه النص.
- إدخالات الاختبار في وضع Real يمكن وسمها صراحة `is_demo=true` من الواجهة أو API. البادئة المحجوزة `DEMO-` في معرف المصدر تفرض Demo لحماية ملف العينة عند استخدام النموذج الحقيقي.

## معنى الإحصاءات والتصحيحات

إجمالي الرسائل هو عدد السجلات بعد إزالة إعادة الاستيراد. الشكاوى عدد الرسائل ذات الحالة الحالية `is_complaint=true`. التوزيع حسب الفئة يستخدم الشكاوى فقط، وتعرض الشكاوى غير المصنفة منفصلة.

حصة النظام هي عدد الشكاوى المرتبطة به ÷ جميع الشكاوى في النطاق المختار، بما فيها غير محدد النظام. كل رسالة لها نظام وفئة رئيسية واحدة في P0.

`data_scope=real` افتراضي في API؛ واجهة Mock تختار `demo` صراحة. لا يوجد جمع تلقائي بين النطاقين. تصحيح سجل Demo لا يحوله إلى بيانات حقيقية.

رسوم النشر تستبعد السجلات بلا تاريخ أصلي وتعرض عدد الشكاوى غير المؤرخة ضمن نطاق المصدر/النظام، قبل فلتر الفترة التي لا يمكن إسنادها إليها. اختيار «وقت الاستيراد» يعرض نشاط إدخال البيانات، وليس تاريخ حدوث المشكلة. النقاط الزمنية المعروضة هي الفترات التي تحتوي شكاوى؛ لا تُختلق تواريخ أو أعداد لفترات غير مرصودة.

التصحيحات تحفظ داخل معاملة واحدة وتؤثر على القيم الحالية والمؤشرات. التوقع الأصلي ونسخته ودرجاته تبقى محفوظة في `original_prediction`، واسم النظام الأصلي محفوظ. درجات النتيجة الأصلية لا تصف بالضرورة الفئة التي صححها الإنسان. لا يوجد تدريب تلقائي أو تعديل لأوزان ML.

## قاعدة البيانات والخصوصية

قاعدة SQLite المحلية: `app/backend/storage/complaints.sqlite3`، مستبعدة من Git. إنشاء الجداول غير هدام. الاختبارات تستخدم قواعد منفصلة مؤقتة.

التنقيح يحجب أنماط البريد الإلكتروني وأرقام الجوال السعودية والهوية ذات الشكل المعروف قبل التصنيف والتخزين، ويطبّق على اسم النظام أيضًا. هذه قواعد محدودة؛ لا تضمن إزالة جميع الأسماء أو المعلومات الشخصية. لا يُحفظ الملف المرفوع أو النص الخام. راجع البيانات قبل مشاركة القاعدة.

`DATABASE_URL` يسمح باختيار قاعدة أخرى. النماذج واستعلامات التجميع قابلة للنقل، لكن **لم يُنفذ أو يُختبر ترحيل PostgreSQL**. نقل البيانات وتثبيت driver وخطة migration لاحقة؛ `create_all` ينشئ الجداول الناقصة ولا يحدّث بنية جدول موجود تلقائيًا. انسخ قاعدة البيانات احتياطيًا قبل أي تغيير مستقبلي للبنية.

## دمج نموذج Claude

```bash
APP_ML_MODE=real npm --prefix app run start
```

تم دمج تسليم A4 `aa4b394` من فرع Claude عبر subtree دون تغيير محتواه، فوق دمج V1 السابق `a02d2fa`. اعتماديات A4 الأصلية في `ml/requirements-a4-inference.txt` ويضمها `backend/requirements-a4.txt` مع Backend المتوافق؛ اعتماديات V1 وبيئته محفوظة. مسار P0 يستدعي:

```python
from ml.infer import predict_text
result = predict_text("التطبيق بطيء")
```

مسار P1 يستدعي أيضًا ml.analyze.analyze / extract_text عبر عقد مستقل محيط بالتنبؤ. تبقى المفاتيح الستة المتفق عليها كما هي. اختيار Real لا يتطلب تغيير صفحات React. النموذج الغائب أو النتيجة المخالفة للعقد ينتجان خطأ HTTP 503 صريحًا؛ لا fallback إلى Mock ولا إعادة تحليل تلقائي للسجلات السابقة.

بدء الخادم ينفذ استدلال إحماء حقيقيًا غير محفوظ، ثم تعرض صفحة المعلومات حالة نجاح الاستدعاء؛ هذا لا يعني قياس دقة الموديل. تعرض النسخة المدمجة `ml/reports/a4_model_card.md` عند تشغيل A4 من مساره المعتمد، أو `ml/reports/evaluation.md` عند الرجوع إلى `tfidf-baseline-v1`. يحافظ تقرير A4 على فصل holdout_all/random/enriched/codeswitch، وexternal AURA proxy، وV1 test الموصوف صراحة NON-BLIND؛ لا تجمع نتائج مجموعات مختلفة أو تقارنها باعتبارها الاختبار نفسه. التقرير يوضح أن المراجع AI-assisted وليست human gold؛ يُعرض نصه كما هو ولا تُولد منه مقاييس جديدة. عند تخصيص `ML_ARTIFACT_DIR` لمسار غير المسارين المعتمدين يُعطّل التقرير التلقائي، ويجب ربط تقرير النسخة المخصصة صراحة:

```bash
APP_ML_MODE=real \
APP_EVALUATION_REPORT="/absolute/path/to/ml/reports/evaluation.md" \
APP_EVALUATION_MODEL_VERSION="exact-model-version" \
npm --prefix app run start
```

يظهر التقرير فقط إذا تطابقت نسخته المحددة مع نسخة آخر استدلال Real ناجح. يعرض كنص المصدر لا HTML. مسؤولية صحة التقرير ونسبته للنموذج لصاحب تقرير ML. التطبيق لا يحسب أو يولد تقييمًا علميًا.

## الواجهة ثنائية اللغة والتحليلات المطورة

زر **عربي / EN** أعلى الموقع يبدل لغة التنقل والعناوين والأزرار والنماذج، ويغيّر الاتجاه إلى RTL أو LTR. يُحفظ الاختيار محليًا في المتصفح تحت المفتاح `marsad.language`، والعربية هي الافتراضية. محتوى الشكاوى وأسماء الأنظمة وفئات النموذج والنتائج البحثية لا تُترجم ولا تُرسل لخدمة ترجمة. الأعداد والنسب ودرجات الموديل وأرقام التواريخ والأوقات تُعرض بالأرقام الإنجليزية `0–9` في اللغتين؛ توقيت الرياض والتقويم الميلادي محفوظان.

الداش بورد المطورة تضيف:

- رسمًا دائريًا لتوزيع الفئات وروابط تنقل إلى الرسائل التابعة لكل فئة.
- ترتيب الأنظمة مع روابط إلى رسائل النظام، ومصفوفة «نظام × فئة» في تحليلات الأنظمة مع البحث والفرز وعرض البطاقات.
- مؤشرات اكتمال بيانات أسماء الأنظمة وتواريخ النشر، ونسبة الرسائل التي لا تتطلب مراجعة إضافية **حسب حالتها الحالية**. هذه ليست دقة للنموذج ولا دليلًا على مراجعة بشرية فعلية لكل رسالة.
- مزيج المصادر: عدد الرسائل وعدد الشكاوى لكل من الإدخال النصي وCSV.
- مقارنة عدد الشكاوى بالفترة السابقة المساوية في عدد الأيام عند اختيار **بداية ونهاية** للفترة. تحافظ المقارنة على المصدر والنظام ونطاق Demo/Real وأساس التاريخ. نسبة التغير غير متاحة إذا كان عدد الفترة السابقة صفرًا.
- اختصارات آخر 7/30 يومًا حسب توقيت الرياض، وإمكانية عرض نشاط الاستيراد الفعلي عند غياب تواريخ نشر.

مؤشرات الاكتمال تخص السجلات ضمن الفلاتر الحالية؛ نسب الأنظمة والتواريخ تُحسب من الشكاوى، ومؤشر عدم الحاجة للمراجعة من جميع الرسائل. محتوى النموذج والتقارير وأسباب أخطاء المصدر تظل كما وردت دون إعادة صياغة آلية.

## نتيجة قبول الدمج وحدوده

راجع `INTEGRATION_VERIFICATION.md` لدليل الاختبارات والمتصفح. مخزن التحقق المحلي منفصل عن قواعد المستودعات الأصلية، ولا تمثل أمثلة التحقق مجموعة تقييم بحثية. تبقى سجلات Mock القديمة Demo ولا يعاد تحليلها تلقائيًا.

- الاستدلال يعمل دون الإنترنت أو inference API؛ تثبيت الاعتماديات أول مرة يحتاج ملفات محلية أو اتصالًا بمستودع الحزم.
- شُغلت اختبارات ML الأصلية ببياناتها المحلية المجمدة دون تعديل أو إعادة توليد labels/splits/نتائج تقييم. في checkout جديد انقل بيانات Claude المحلية المسموح بها إلى مواضعها نفسها لتشغيل اختبارات التسرب كاملة؛ بعضها يتخطى البيانات الغائبة وفق تعليمات Claude الأصلية. اختبارات دمج التطبيق لا تتخطى غياب الأوزان، بل تفشل بوضوح.
- لتشغيل اختبارات التطبيق الوحدوية فقط دون أوزان: `app/backend/.venv-p1/bin/python -E -s -m pytest -c app/backend/pytest.ini app/backend/tests -m 'not integration' -q`.
- مثال OTP المختلط أعاد AUTH مع A4، بينما أعاد «غير شكوى» مع V1 في فحص الرجوع. هذا مثال تشغيل فقط، وليس مقياس دقة أو دليلًا على صحة كل نص مختلط.
- `needs_review=false` يعني عدم طلب مراجعة إضافية حسب الحالة الحالية، ولا يثبت إجراء مراجعة بشرية.
- اسم النظام المجهول يظل غير محدد؛ يضيف P1 استخراجًا محافظًا للأسماء وOCR عبر عقد منفصل، دون تدريب جديد.

قاعدة الفحص المؤرشفة محليًا: `app/backend/storage/verified-e2e.sqlite3` (مستبعدة من Git)، وتحتوي أمثلة تحقق وليست بيانات تقييم علمي. القاعدة الافتراضية أُعيدت إلى نسختها الأولية: تسع رسائل Demo مستبعدة من الإحصاءات الحقيقية، دون أي رسائل اختبار Real. للاطلاع على دورة الفحص المحفوظة فقط يمكن التشغيل من `integration/` بالأمر:

```bash
DATABASE_URL="sqlite:///$PWD/app/backend/storage/verified-e2e.sqlite3" npm --prefix app run start
```

## اختيار A4 والرجوع إلى V1

الـlauncher يقرأ `app/.env` تلقائيًا، وتبقى القيم المقدمة في بيئة shell ذات أولوية. القيم الأساسية:

```dotenv
APP_PYTHON=backend/.venv-p1/bin/python
APP_ML_MODE=real
ML_ARTIFACT_DIR=ml/artifacts/a4/export/a4-marbert-v1
HF_HUB_OFFLINE=1
TOKENIZERS_PARALLELISM=false
```

مسار APP_PYTHON النسبي محسوب من `app/`، وML_ARTIFACT_DIR من `integration/`، لأن هذه نقطة تشغيل Backend. النسخة الحالية تستخدم CPU وتحمل نحو 1.5GB من الذاكرة. يحتاج البدء البارد بضع ثوانٍ؛ FastAPI لا يبدأ قبول الطلبات حتى ينتهي الإحماء، والـlauncher ينتظر إتاحة تشخيص Backend قبل بدء Vite لتجنب أخطاء الاتصال المؤقتة. الحد الأقصى لانتظار بدء Backend في launcher هو 120 ثانية؛ فشل الموديل نفسه يبقي التشخيص متاحًا دون fallback. إذا افتقد الملفات أو فشل التحميل يظهر خطأ تكامل؛ لا fallback إلى Mock أو V1.

للرجوع إلى V1: أوقف **نسختك** من الخادمين، احذف سطر `ML_ARTIFACT_DIR` من `app/.env`، ونفّذ `unset ML_ARTIFACT_DIR` في shell إذا كان مُصدّرًا، ثم شغّل `npm --prefix app run start`. لا تحذف الأوزان ولا تعدّل manifest. النموذج مخزّن لكل process، لذلك تغيير متغير البيئة دون إعادة تشغيل لا يبدله. لإعادة A4 أعد السطر وأعد التشغيل. تبقى نسخ كل التنبؤات وتصحيحاتها محفوظة؛ لا إعادة تحليل للسجلات القديمة.

بيئة P1 المستقلة تشغّل A4 وV1، ولا تحتاج تغيير APP_PYTHON عند الرجوع إلى V1. بيئة V1 الأصلية وبيئة A4 السابقة محفوظتان دون تغيير للاستعادة فقط؛ لا تحميل حزم منهما في الإعداد الحالي. عند غياب `.env` يبقى سلوك launcher القديم للرجوع إلى بيئة V1 الأصلية كما كان.

التوثيق التفصيلي والأدلة: `A4_INTEGRATION_VERIFICATION.md`. قاعدة الفحص الحالية المؤرشفة `backend/storage/a4-e2e.sqlite3` (مستبعدة من Git) تضم أمثلة تشغيل عبر النسختين، ولا تُستخدم كبيانات بحث. إزالة DATABASE_URL التجريبية من `.env` تعيد القاعدة المحلية العادية دون أي تعديل لبياناتها.

التحقق من استقلال البيئة ونتائج اختبارات هذه المرحلة في `ENVIRONMENT_VERIFICATION.md`. يوجد cache تثبيت اختياري متحقق منه تحت `backend/.wheelhouse-a4`؛ ليس جزءًا من اعتماديات وقت التشغيل. لا حاجة إلى إعادة تدريب أو تقييم holdout أو تعديل أي عقد API.


مسار النص في وضع Real يستخدم `POST /api/complaints/analyze-p1`؛ وضع Mock يحتفظ بمسار P0 الواضح وبيانات Demo. مسار الصور يستخدم `POST /api/ocr/extract` ثم زر تأكيد مستقل يرسل draft_id والنص المصحح. الأسماء المحتملة لا تصبح أسماء مؤكدة، وذكر عدة أنظمة لا يختار نظامًا رئيسيًا من تلقاء نفسه. الشكاوى القديمة تظل دون P1 provenance ولا يعاد تحليلها. تصحيح OCR يحفظ الأصل والتعديل في سجل التصحيحات؛ لا تُحفظ الصورة. مؤشرات الأنظمة تعتمد الحقل الفعّال القابل للمراجعة، ولا تعني تحديد سبب العطل.
